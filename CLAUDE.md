# CLAUDE.md — инструкции для ИИ-агента в этом репозитории

Проект: риск-сводка по синтетическому кредитному портфелю.
Стек: PostgreSQL 16 → семантическая модель YAML → дашборд Vega-Lite (статичный HTML + vega-embed).

## Источники и бизнес-правила (не менять без согласования)
- `data/portfolio.csv`: два месячных среза (01.09.2026, 01.10.2026). `principal_outstanding` — в валюте кредита.
- `data/fx.csv`: курс к тенге по дням. Конвертация — **по курсу на дату среза** (`report_date`), не на конец месяца.
- Портфель = Σ остаток × курс, **без списанных** (`written_off = 1`) на эту дату.
- PAR30 / PAR90 — доля портфеля (по сумме, не по штукам) с просрочкой **строго >** 30 / > 90 дней.
- NPL — просрочка > 90 **или** `restructured = 1`.
- Провизии: NPL → 50%; иначе 31–90 дн. → 10%; иначе (0–30 дн.) → 1%. NPL имеет приоритет.
- Концентрация — доля 10 крупнейших `group_id` по сумме в тенге, отдельно на каждую дату.

## Известные особенности данных
- 60 полных дублей строк (по 30 на дату) — удаляются через `SELECT DISTINCT` в `v_loan_snapshot`.
  Если появятся неполные дубли по ключу `(report_date, loan_id)` — тест должен упасть, а не «молча выбрать» строку.
- 23 кредита списаны на 01.09, но активны на 01.10. По определению входят в октябрьский портфель; показываем отдельно.
- 421 / 438 активных кредитов (≈20% портфеля) с истёкшим `maturity_date`, большинство с DPD = 0 —
  флаг `is_past_maturity`, не исключаем, выносим как вопрос к владельцу данных.

## Правила работы
- Слои: `raw` (как есть, text-колонки) → `reporting` (только VIEW, `CREATE OR REPLACE`). Никаких таблиц в `reporting`.
- Все скрипты идемпотентны: загрузка raw = `TRUNCATE + \copy` в одной транзакции.
- Порядок колонок существующих вьюх не менять (ограничение `CREATE OR REPLACE VIEW`); если нужно — дописывать колонки в конец.
- Избегать коррелированных подзапросов к вьюхам (были O(n²)) — использовать оконные функции.
- Любая новая метрика: (1) SQL-вью, (2) тест в `sql/90_tests.sql`, (3) пересчёт в `checks/reference_metrics.py`, (4) мера в YAML.
- В Vega-Lite при `sort` по полю в многослойных графиках указывать `op: "min"/"max"` (иначе сортировка молча отбрасывается).
- Палитру графиков проверять валидатором CVD; красный и оранжевый в одном графике не использовать.

## Команды
```bash
./scripts/build.sh     # схемы, загрузка, вьюхи, тесты, экспорт данных дашборда
./scripts/verify.sh    # независимый пересчёт на Python + валидация YAML
python -m http.server 8000 --bind 127.0.0.1 --directory dashboard   # дашборд
```

## Definition of done
1. `build.sh` проходит дважды подряд, выгрузки побайтово совпадают (идемпотентность).
2. `verify.sh`: `RECONCILIATION: OK` и `SEMANTIC MODEL: OK`.
3. Дашборд открыт и просмотрен глазами (скриншот) на 1400px и 375px: в консоли нет ошибок и предупреждений Vega-Lite,
   страница не шире экрана, подписи не обрезаны.
4. Цифры в README совпадают с базой (сверять запросом, не на глаз; округлять один раз от точного значения).
5. Сборка проходит из чистого `git clone` на пустой БД; `scripts/*.sh` в git с режимом `100755`.

## Безопасность
- Пароли только в `.env` (в `.gitignore`), в репозитории — `.env.example`. Не печатать секреты в вывод.
- Postgres слушает только `127.0.0.1`. В `docker run` порт публиковать как `127.0.0.1:5432:5432`.
- CDN-скрипты — с фиксированной версией и SRI-хэшем; данные в HTML вставлять только через `textContent`.
- Не коммитить: `.env`, дампы, каталоги данных PostgreSQL, логи.
